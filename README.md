# ⋄ Name_313 ⋄
Репозиторий проекта по созданию сквозного пайплайна обработки, анализа и загрузки данных.

В процессе развития проекта были реализованы три ключевых модуля:
1. **Анализ и подготовка табличных данных**: Разведочный анализ (EDA), приведение типов и сохранение в формат Parquet.
2. **Сбор данных через API**: Опрос публичного API и формирование нового датасета.
3. **ETL-пайплайн**: Пакет для извлечения, трансформации и загрузки данных в реляционную базу данных (PostgreSQL).

## Часть 1: Первичный анализ данных (EDA)

### Данные :floppy_disk:
Используемый в проекте датасет взят с **[Kaggle](https://www.kaggle.com/datasets/deepashukla/unified-credit-and-carbon-dataset-for-rural-ai?resource=download)**.

Датасет содержит финансовые, психометрические, категориальные, числовые и геопространственные признаки.
- Объём файла: 1,2 МБ
- Количество записей: 5 000
- Количество признаков: 33 (включая 2 целевые переменные)

### Результаты анализа
Подробный EDA представлен в ноутбуке `notebooks/EDA.ipynb`. В ходе анализа были выявлены:
- Логические аномалии (например, отрицательные значения в `soc_percent`).
- Скрытые пропуски (31% в `education_level`).
- Отсутствие линейных корреляций между признаками (матрица корреляций в пределах ±0.04), что обосновывает применение нелинейных ML-алгоритмов.

## Часть 3: ETL-пайплайн и загрузка в БД
### Описание архитектуры :card_file_box:

Пакет src/etl обеспечивает полный цикл подготовки данных: от загрузки сырого датасета до записи результата (100 строк) в удаленную БД PostgreSQL. Пакет не зависит от внешних скриптов.

> [!WARNING]
> Для работы пайплайна в корне проекта должен находиться файл *creds.db* с учетными данными. Этот файл добавлен в .gitignore и не попадает в репозиторий по соображениям безопасности.

### Запуск ETL-пайплайна :jigsaw:

Для запуска используется CLI-интерфейс с указанием количества строк (по умолчанию 100):

```bash
python -m src.etl.main --limit 100
```
### Особенности реализации:
- Extract: Проверяет целостность скачанного файла с помощью MD5-хеша. Если файл поврежден, он скачивается заново.
- Transform: Осуществляет валидацию данных (проверка на пустоту).
- Load: Подключается к PostgreSQL через SQLAlchemy, загружает данные в таблицу khitrykhav и выполняет контрольный запрос SELECT COUNT(*) для подтверждения успешной записи.
